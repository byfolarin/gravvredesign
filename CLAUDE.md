# Gravv web redesign — project context

Redesign of the **Gravv** dashboard (Kredete's stablecoin payments platform: wallets,
transactions, payouts, payment links). Prototype only — all data is seeded placeholder data,
nothing persists. Owner: Folarin (product designer).

## Run it

- **Two builds (Oct 22, 2026):** `main` = **Current** experience, frozen — don't change product code there unless asked. `review` = **Review**, where new changes go, checked out as a git worktree at `../gravv-web-redesign-review` (own node_modules; run `npx next dev -p 4001` there). Main runs on 4000. Top bar has a **Current | Review** switch (`app/_components/experience-switch.tsx`, `HERE` differs per branch) that jumps to the same path in the other build (local 4000↔4001; live current = gravv-web-redesign.vercel.app, review = gravv-web-redesign-review.vercel.app — not deployed yet).

- `npx next dev -p 4000` → http://localhost:4000
- **Stale CSS gotcha:** Turbopack often keeps serving an old `app/globals.css`. After editing it,
  check the served chunk (`curl` the page's `/_next/static/...css` and grep for the new token);
  if it's missing: stop the server, `rm -rf .next`, start again.
- Next 16 with `cacheComponents: true` → pages stay alive in the background (React `<Activity>`).
  Anything that should replay on every visit must reset in a `useLayoutEffect` cleanup
  (see `app/_components/roll.tsx`). Read `node_modules/next/dist/docs/` before Next-specific work.
- React Compiler lint forbids synchronous `setState` in effects — defer with `setTimeout`.
- Check: `npx tsc --noEmit && npm run lint`.

## How the owner works (important)

- **Confirm direction before big builds**, but don't bury them in option lists — they dislike being
  re-asked things they've already answered.
- Hates generic, "junior" dashboards and decoration: no decorative dots, toy device mockups,
  dot-grid canvases, chip soup, or colour without meaning.
- When a page should follow a product, look at the real screens first (Mobbin MCP is available),
  e.g. **Payment links = Mercury's Requests/Invoicing pattern**.
- Each page doesn't have to copy the others' layout — consistent tokens, different composition.
- Nour countdown (`app/_components/countdown`) stays unmounted unless explicitly asked for.

## Design system (keep consistent)

- **Screen-size scaling:** the app is designed at full size for big monitors and scales down as one on smaller screens via `html { zoom: var(--app-zoom) }` (globals.css): 1 at ≥1800px, 0.94 (also MacBook Pro 14", 1512px) / 0.82 / 0.78 below. Don't use `h-screen`/`100vh` for full-height layouts — use `.app-fill` / `.app-fill-min` or `calc(100dvh / var(--app-zoom) - …)` so zoomed layouts still fill the window. Page columns use `max-w-(--page-max)` (1180px, 1280px below 1800px) and `max-w-(--page-max-narrow)` (1080 / 1160) — never a hard-coded width.
- Headline money: small grey unit (13px) and quiet subscript cents after the figure (`<Usdc big />` in Collections) — the unit never competes with the number.

- **Accessibility (light theme):** status text and fills are remapped in globals.css so every chip's text is ≥ 5.5:1 on its own tint (Provisioning 7.0, Closed 5.8, Active 6.4, Needs info 5.6, Declined 6.4); secondary grey `--color-neutral-500` is #5c5c5c. In light, `text-black` = paper white — on mint fills use the fixed ink `text-[#04301c]` instead. Measure with a canvas-blended contrast check, not by eye.
- **Light theme is paper white, not screen white** (owner's call): `--surface #fbfaf7`, `--surface-2 #f6f5f1`, `--raised #fdfcfa`, `--takeover #f8f7f3`; don't hard-code `#fff` surfaces.
- Fonts: Geist + Geist Mono (local `geist` package). Dark first; light theme under
  `[data-theme="light"] .content-theme`. Theme switch (Light / Dark / System) in the sidebar footer.
- Weights: page titles and headline numbers are **font-medium**, never semibold.
- Colour: brand mint `--brand` / `--flow-in` means money in / good; grey `--flow-out` for out.
  Status chips: every state its own soft hue — Completed/Active/Verified mint (`--ok-bg`/`--ok-fg`), Pending/Settling amber, Provisioning/Verifying/Under review blue, Failed/Declined/Action needed rose; no grey dashed outlines for live states.
- **Colour with a job** (`app/_components/tone.ts`): People always get a real portrait (`photoOf` in person-avatar.tsx — set photo or a stable one from their name, matched to gender by first name); `toneFor(name)` tints business initials. No type-arrow icon squares in tables (owner removed them). Money in reads mint (`--ok-fg`), money out ink; the selected pill tab and active filters are **ink** (black on paper / white on dark — owner rejected mint for selection; global rule + Dropdown `active`); mint means money in / success only. Business logos in colour, not greyscale.
- Amounts: tabular nums, small cents in `<sub>` **on the figure's baseline** (global `sub { bottom: 0 }` — owner rejected raised and dropped cents); headline numbers roll in with `<Roll>`
  (`app/_components/roll.tsx`) on every page enter. Mark money with `.amount` so "Hide amounts"
  (top bar eye or ⇧H) can hide it — hidden figures are **pixelated** (8px mosaic via SVG filter `#gravv-pixelate` mounted in the top bar, applied in `globals.css`). Owner rejected blur and redaction bars.
- Shared parts: `Dropdown` (`app/_components/dropdown.tsx`), `CopyButton`, `Roll`,
  `TopBar` (search · "Updated n min ago" (click = refresh) · **Move money ▾** menu (Send money / Request payment / Convert currency) · │ · hide amounts (eye, ⇧H) · settings · bell = **Inbox** (`app/_components/inbox.tsx`, a panel under the bell — Lovable/Remote pattern; owner hated a first full-height drawer list as "ChatGPT design"): segmented **Notifications** / **Promotions**. Notifications = **Needs you** (`NEEDS` in `notifications-data.ts`: sentence with **bold** name/amount, the person's photo with a small tinted badge for what it's about, the warning on its own line in the tone colour, plain facts under it, actions done in place — Approve / Retry now / Send reminder → "done" line + Undo — or on their page — Review / Respond / Update details; "38 more waiting") then **Activity** (one-sentence rows, read = quieter, quotes for comments, archive on hover, Mark all read). Bell count = what still needs you. Promotions = newest update large, the rest as thumbnail rows, link to What's new; opened from anywhere with `openInbox(tab)`),
  sidebar with Hugeicons stroke icons.
- Sheets/flows with typed input must not lose it to a stray click: once dirty, scrim click / Esc / × ask "Discard …? [Keep editing] [Discard]" (Esc = keep). Use `useDiscardGuard(close, touched)` + `DiscardConfirm` (`app/_components/discard-guard.tsx`); pass `touched` computed from the flow's own state (any choice made) — input events alone miss picks from custom lists (Open account's customer picker discarded silently); `[data-keeps-clean]` excludes controls, `clear()` on success. Every create/send flow has it.
- Bar charts: shared `BucketBars` (`app/_components/bucket-bars.tsx`) — day (30D) or week (90D) buckets, optional stacking with 2px gaps, left value axis, hover tooltip dims the rest, click a bar to filter the table (banner with Clear), summary line + range switch + "Hide chart" pill, sits on the same soft panel as Wallets/Transactions (Trade desk is the exception — owner rejected a panel there), open by default and remembered. Used by Payment links ("Collected", USD-eq, avg line, top links in tooltip).
- Discard guards set their dirty flag in a `setTimeout` — setting state during the input event made controlled inputs drop the first character typed.
- Loading: use `LoadingState` (`app/_components/loading-state.tsx`, owner-supplied) with **variant Drive everywhere**, and **no skeletons** — a loading state is the Drive loader alone, centred where the content goes (owner's call; Dots/Orbit/Surfer exist but aren't used); keyframes `pixel-on` / `shimmer-text` / `pop-in` in globals.css; ink = `--color-white` so it works in both themes. 
- Table hierarchy: header row on a grey band — applied to every table by a global rule in globals.css (`.content-theme thead > tr`), medium weight, neutral-400; the row's lead (customer / name) medium 13.5px white — never semibold; supporting columns (date, IDs) muted; second lines 12px with a 4px gap.
- **Product updates** (`app/_components/updates-data.ts` list + `updates.tsx` UI): real product screenshots (`public/updates/*.png`) on soft two-stop gradients — the one place gradients are used. Shown in: sidebar "New" card above your name (one at a time), an on-page **`UpdateNotice`** under the header of almost every page — a **stack**: the page's own update in front, the newest other undismissed updates (max 3) peeking behind; click the stack to fan them out (Show less / All updates below); the front card's stack symbol (Layers + total count) opens the **Inbox** on its Promotions tab (`openInbox("promotions")` from `inbox-events.ts`). Each card is (screenshot · "New · title" · one `line` · black action button · ×; a brand-mint dither on the right: solid soft green at the edge, breaking into ~8px pixels; the field covers the right 25% of the card (scales with it) — owner rejected a dense scatter). Each page shows a relevant update: Transactions + Billing u-hide (button toggles hide amounts), Wallets u-desk, Accounts u-plans, Recipients + Team u-approval, Customers + Payment links u-checkout, Collections u-disputes, Disputes u-funnel, Approvals u-recipients, Trade desk u-candles (opens a chart). And the `/whats-new` page (avatar menu → What's new). Dismissals per place in localStorage.
- **Soft colour with a job** (`app/_components/pixel-field.tsx`): `PixelField` (solid colour at one edge dithering into ~8px pixels, then gone; pass `cols`/`rows` matching the box so pixels stay ~8px) and `wash(tone, at, strength)` (soft radial tint from a corner; mint = good / money in, blue = in progress, amber = needs you). Used on moments and cards whose state means something — never behind tables or numbers you read closely, one per card. First applied on **Accounts**: balance panel stays open on the page — no container, no wash (owner removed it); "No accounts yet" is a hero card (mint wash + dither from the bottom-right), empty-currency box mint (blue while one is being set up), and the Open account flow's summary card lights up mint + dither once requested. Other pages pending the owner's verdict on Accounts.
- Tab counts sit on the label's line at the same size, just quieter in colour (global rule `.content-theme [role="tab"] > span.tabular-nums`). Table headers: grey fill, no rule lines.
- **Paging:** every table uses `usePager(rows, key)` + `<TablePager>` (`app/_components/table-pager.tsx`): "Showing 1–20 of N · Rows per page [10/20/50/100]" + page buttons, default 20, remembered per table in localStorage (`gravv-page-size-{key}`). No "Show more".
- Tables: hairline rows, row click expands an inline preview, "View all details" opens a right sheet;
  bulk selection uses a black floating bar (`theme-lock-dark`, black in both themes — Cards' grey inline strip was replaced); ⋮ row menus. Summary/fact strips: label 13px neutral-400 · 26px medium figure · 12px note, columns split by hairlines (Trade desk facts, Transactions summary).
